# 第一阶段：服务、MySQL 迁移与评测运行

更新日期：2026-11-19。

## 范围与文件职责

本阶段建立最小 Spring Boot 服务，只保存评测运行的元数据。没有逐例结果、报告导入、模型调用、费用计算或人工复核接口。

依赖选型依据：[Spring Boot 4.1.2 发布公告](https://spring.io/blog/2026/10/23/spring-boot-4-1-2-available-now/)、[Spring Boot 4.0 迁移说明](https://github.com/spring-projects/spring-boot/wiki/Spring-Boot-4.0-Migration-Guide)、[MyBatis 4.1 Starter 与 Spring Boot 4.1 的兼容说明](https://github.com/mybatis/spring-boot-starter)。由于 IntelliJ 的 Mend.io 扫描对旧版传递依赖给出安全告警，本轮将框架更新到受维护的 4.1 系列，并按迁移说明改用 Web MVC、Flyway 和 Web MVC 测试 Starter；安全扫描结论仍以实际扫描结果为准。

## 数据流和表

`POST /api/runs` 校验请求后生成 UUID、UTC 创建时间；事务服务经 MyBatis 写入 `eval_runs`。`GET /api/runs/{id}` 按 ID 读取，`GET /api/runs` 按创建时间倒序列出最近记录，可按来源项目筛选，最多 100 条。服务启动时 Flyway 先迁移，再开放接口；迁移记录在 Flyway 自身的 `flyway_schema_history` 表。

`eval_runs` 保存 `id`、`source_project`、`run_label`、`dataset_version`、可空的 `model_id` / `prompt_version`、`result_source`、`status`、`started_at` 和 `created_at`。时间按 UTC 写入 `DATETIME(3)`；连接 URL 要使用 UTC 会话。`result_source` 明确区分 `LIVE_MODEL`、`OFFLINE_FIXTURE`、`HUMAN_REVIEW`；这些是来源标签，服务目前不核验真实模型输出或人工审核事实。`status` 为 `RUNNING`、`COMPLETED`、`FAILED`。`run_label` 是自由文本，不能替代正式模型或提示词版本。

## 配置与启动

需要 Java 17、Maven 和 MySQL 8。先由数据库管理员创建一个**空库** `llm_eval_hub`，并给专用账号该库的建表与读写权限；不要把账号密码写入仓库。PowerShell 示例：

```powershell
$env:JAVA_HOME = 'E:\java17' # 改为本机 JDK 17 路径
$env:Path = "$env:JAVA_HOME\bin;$env:Path"
$env:DB_URL = 'jdbc:mysql://127.0.0.1:3306/llm_eval_hub?connectionTimeZone=UTC&forceConnectionTimeZoneToSession=true'
$env:DB_USER = 'llm_eval_hub'
$env:DB_PASSWORD = '<从本机安全来源设置>'
mvn -B package
java -jar target\llm-eval-hub-0.1.0-SNAPSHOT.jar
```

应用默认监听 `127.0.0.1:8080`，可用 `SERVER_PORT` 改端口。数据库不可用或迁移失败时启动会失败，不会伪装成健康。`GET /health` 只表示已启动的进程在响应，并不单独重新检查数据库连接。不要把 PowerShell 示例中的占位密码直接用于实际运行。

## HTTP 契约

创建示例，请求不包含原文、提示词或密钥：

```http
POST /api/runs
Content-Type: application/json

{"sourceProject":"qa-system","runLabel":"本地示例","datasetVersion":"dataset-v1","modelId":"model-a","promptVersion":null,"resultSource":"OFFLINE_FIXTURE","status":"COMPLETED","startedAt":"2026-11-19T00:00:00Z"}
```

成功返回 `201 Created`，`Location: /api/runs/{id}`，响应包含上述字段及服务器生成的 `id`、`createdAt`。`GET /api/runs/{id}` 返回相同结构，未知 ID 返回 404。`GET /api/runs?sourceProject=qa-system&limit=20` 返回数组；`limit` 范围 1～100，默认 20。无效或缺失的必填字段返回 400。`sourceProject` 只接受 1～64 位字母、数字、下划线或连字符。没有更新、删除、分页游标、鉴权或去重接口；本阶段只在本机绑定地址使用，不应直接暴露公网。

## 验证记录与限制

2026-11-19 在 Windows 11、Oracle JDK 17.0.12、Maven 3.9.16 运行 `mvn -o -B '-Dmaven.repo.local=D:\llm-eval-hub\.mvn\repository' test` 和同参数的 `package`，均 `BUILD SUCCESS`；4 项 `@WebMvcTest` 通过。`-Dmaven.repo.local` 只把本轮下载的依赖缓存留在仓库内的忽略目录，普通环境可省略；`-o` 需要依赖已在缓存中。测试覆盖创建响应与 `Location`、必填来源缺失和超出范围的 `limit` 返回 400、未知 ID 返回 404。测试中的 Service 是模拟对象，数据库验证另行执行。

使用本机已有的 `mysql:8.4` 镜像启动一次性容器（仅绑定 `127.0.0.1:33307`，虚构账号和口令，结束后容器已停止并自动删除），空库首次启动时 Flyway 成功应用 V1。对本机服务 `127.0.0.1:18080` 的实际请求得到：`POST /api/runs` 返回 201 和 `Location`；按 ID 查询返回同一记录，按项目列表返回 1 条，`GET /health` 返回 `UP`；缺失 `resultSource` 返回 400，未知 ID 返回 404。直接查询隔离库确认 `flyway_schema_history` 中 V1 成功，`eval_runs` 有 1 条 `qa-system` / `OFFLINE_FIXTURE` 记录。服务重启后 Flyway 报告 schema 已是 V1、无新迁移，原记录仍可查询。

上述首次验证使用 Spring Boot 3.5.16。针对 IDE 提示的旧版传递依赖安全告警，随后更新到 Spring Boot 4.1.2、MyBatis Starter 4.1.0 和框架管理的 Flyway 12.4.0；在 Oracle JDK 17.0.12、Maven 3.9.16 上运行 `mvn -B '-Dmaven.repo.local=D:\llm-eval-hub\.mvn\repository' verify`，构建成功，4 项 HTTP 测试全部通过。再次以一次性 MySQL 8.4 空库启动新版 JAR，Flyway V1 成功迁移；`POST /api/runs` 返回 201，按 ID 和项目查询均返回新记录，`GET /health` 返回 `UP`。本次启动日志没有旧版 Flyway 的 MySQL 8.4 正式测试范围提示。Maven 构建通过不代表 IDE 的第三方安全扫描无告警；旧的 20 条检查结果仍可能留在 IDEA 窗口中，需要以重新扫描当前依赖的结果为准。

尚未做自动化 MySQL 集成测试、并发/负载测试或跨项目联调。第二阶段才会定义报告导入、逐例结果和去重；本阶段写入的记录仅是元数据。
