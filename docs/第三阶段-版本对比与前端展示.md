# 第三阶段：同口径对比、失败分类、人工复核与 Vue 展示

更新日期：2026-11-19。

## 本阶段完成的范围

在已有 `qa-system` 评分报告导入能力上，加入运行筛选、同案例集版本对比、可解释的自动失败分类、逐例人工复核历史和独立的 Vue 3 页面。前端位于仓库根目录的 `frontend/`，与 Java 后端分别构建。页面读取当前数据库中的记录；不会生成演示数据。没有修改或调用 `D:\qa-system`、`D:\Agent` 中的应用，也没有运行真实模型。

## 文件职责与数据流

| 文件 | 职责 |
| --- | --- |
| `src/main/java/dev/llmevalhub/run/` | `GET /api/runs` 增加案例集版本、模型标识的精确筛选；仍最多返回最近 100 条 |
| `src/main/java/dev/llmevalhub/comparison/` | 从导入结果推导失败分类，检查两次运行口径并返回指标差值与逐例失败变化 |
| `src/main/resources/db/migration/V3__create_case_reviews.sql` | 建立逐例审核历史表，与已导入的案例结果建立外键 |
| `src/main/java/dev/llmevalhub/review/` | 校验并保存人工审核，查询单条记录或某运行/案例的审核历史 |
| `frontend/src/api.ts` | 与后端接口对应的 TypeScript 类型及请求函数 |
| `frontend/src/App.vue`、`frontend/src/style.css` | 运行列表、详情、对比、复核四个视图及响应式样式 |
| `frontend/vite.config.ts` | 开发时将 `/api` 和 `/health` 代理到本机后端 `127.0.0.1:8080` |
| `frontend/pnpm-lock.yaml` | 锁定前端依赖，保证可复现安装 |

`eval_case_reviews` 每次提交新增一条记录，保存 UUID、运行 ID、案例 ID、审核人声明、`PASS` / `FAIL` / `NEEDS_FOLLOWUP`、可选说明与 UTC 时间。记录不覆盖，页面显示最新结论和该案例的历史。数据库外键阻止给不存在的逐例结果写审核。当前没有登录、身份核验或权限控制；审核人由提交者填写，不能把该字段当作已认证身份。后端只绑定 `127.0.0.1`，不要直接暴露到公网。

## 比较口径与失败分类

`GET /api/comparisons` 只接受两条不同且都已导入评分报告的运行。比较前逐项检查：来源项目、`resultSource`、案例集版本与报告内案例集 SHA-256、`k`、总样本/可回答/拒答分母、案例 ID 集合、每题类别和题型、逐例指标键及定义版本、汇总指标键及定义版本/聚合方式/样本范围/分母/单位。任一项不符返回 409，不计算差值；未知或未导入结果的运行返回 404。**不同来源标签不能混在同一张对比表中。**

差值定义为“候选值 − 基准值”；正负本身不代表改善，例如延迟越低通常越好，而命中率越高通常越好。API 保留原始比例值（0～1），页面显示为百分比，比例差值显示为百分点。缺失的指标值仍为 `null`，不会当作零。逐例对比返回两次运行各自的自动失败分类、新增分类和已消失分类。当前支持的是 `qa-system` 已导入报告；没有将 AI 求职助手指标混入比较。

自动分类是对已落盘评分字段的机械映射，依据 `D:\qa-system\eval\metrics.py` 与本仓库第二阶段保存的逐题字段：

| 代码 | 触发条件 | 含义边界 |
| --- | --- | --- |
| `RETRIEVAL_MISS` | `qa.hit_at_k=false` | 标准证据未进入前 k 个检索结果 |
| `CITATION_PRECISION_BELOW_ONE` | `qa.citation_precision<1` | 引用准确率未达 1；不推断具体原因 |
| `ANSWER_CONTAINS_FAILED` | `qa.answer_contains_all=false` | 答案字面包含检查未过，不等同于语义错误 |
| `REFUSAL_INCORRECT` | `qa.refusal_correct=false` | 拒答检查未过 |

一题可同时触发多项；未触发规则只表示这些检查没有报错，不构成人工审核结论。审核结论独立存储，不会改写原评分指标或自动分类。

## HTTP 接口

| 请求 | 用途与主要响应 |
| --- | --- |
| `GET /api/runs?sourceProject=qa-system&datasetVersion=sha256:<哈希>&modelId=<模型>&limit=100` | 三个筛选项可省略；精确匹配并返回最近运行 |
| `GET /api/runs/{id}/classifications` | 返回每个案例 ID 对应的自动失败代码数组 |
| `GET /api/comparisons?baselineId=<运行ID>&candidateId=<运行ID>` | 返回基准/候选运行、9 项指标及差值、逐例新增/消失失败；口径不一致返回 409 |
| `POST /api/runs/{id}/cases/{caseId}/reviews` | JSON `{"reviewer":"reviewer-1","verdict":"NEEDS_FOLLOWUP","note":"待核对"}`；成功返回 201 和 `Location: /api/reviews/{reviewId}` |
| `GET /api/reviews/{reviewId}` | 查询一条审核记录；未知 ID 返回 404 |
| `GET /api/runs/{id}/reviews` | 查询运行的全部审核历史，按时间倒序 |
| `GET /api/runs/{id}/cases/{caseId}/reviews` | 查询单个案例的审核历史 |

审核人必填且最多 128 字符，说明最多 1000 字符；`verdict` 只能是上述三个值。不存在的运行或案例返回 404。审核历史是追加记录；本阶段没有修改或删除接口。第一、二阶段的导入和运行 API 保持可用。

## 本地启动前后端

后端仍需 Java 17、Maven 3.9.16 和 MySQL 8。先按[第一阶段说明](第一阶段-服务与评测运行.md)设置本机数据库环境变量，再从仓库根目录运行：

```powershell
$env:JAVA_HOME = 'E:\java17' # 换成本机 JDK 17 路径
$env:Path = "$env:JAVA_HOME\bin;$env:Path"
mvn -B verify
java -jar target\llm-eval-hub-0.1.0-SNAPSHOT.jar
```

前端另开一个终端，从 `D:\llm-eval-hub\frontend` 运行：

```powershell
pnpm install --frozen-lockfile
pnpm dev
```

打开 `http://127.0.0.1:5173/`。本机验证使用 Node.js 24.22.3 与 pnpm 11.25.0；锁定 Vue 3.5.45、Vite 8.3.8、TypeScript 5.9.3 等版本。可运行 `pnpm build` 做类型检查并输出 `frontend/dist/`。前端依赖和构建产物被 `.gitignore` 忽略；锁文件应保留。当前是本地开发代理，尚未配置生产环境的前后端托管。没有必要把 `frontend/` 作为 Maven 子模块；可用独立前端编辑器打开，也可在 IDEA 中查看。

本机 IntelliJ IDEA 2025.2.3 免费版在编辑 `main.ts` 时显示“不支持 Vue”及“需要 Node.js”提示，提交前代码分析会误报 `createApp(App).mount()` 未解析。该调用是前端实际使用的入口，`pnpm build` 中的 `vue-tsc --noEmit` 已通过；IDE 的提示不等于 TypeScript 编译错误。`index.html` 使用相对的 `./src/main.ts` 路径，IDE 可定位该文件，Vite 构建也通过。需要 Vue 代码提示时，应使用支持 Vue 的编辑器并配置本机 Node.js；不要仅为消除该误报改写运行代码。

先用[第二阶段说明](第二阶段-qa-system报告导入.md)的方法导入评分报告。运行列表支持来源项目、案例集版本、模型筛选；逐例页展示来源标签、模型声明、报告哈希、汇总指标分母、逐题检查值、分类和最新审核结论；对比页展示同口径差值和逐题变化；复核页保存并显示历史。没有 token 或费用的地方显示“暂无数据”，不会估算费用。
