# 第五阶段：双项目评测上报

更新日期：2026-11-20。

## 完成范围

多用户 RAG 知识库问答系统（`D:\qa-system`）可在评分后显式导入既有格式的报告，再把配对的调用 JSONL 关联到返回的 Hub 运行 ID。AI 求职助手（`D:\Agent\job-agent`）可把规则评估结果存为不含原文的 JSON 报告，显式导入 Hub，并在 live 模式下把调用明细关联到同一运行。两者默认行为均不连接 Hub；没有运行真实模型，也没有把离线夹具通过率称为真实模型质量。

## 接口与数据口径

QA 沿用 `POST /api/imports/qa-system`，相同报告原始字节与相同声明返回原运行 ID；调用使用 `POST /api/runs/{runId}/calls`。原项目新增 `eval/publish_to_hub.py` 作为只重传已有文件的入口，`eval/run_eval.py` 支持评分后显式发布。调用文件保留每次调用的 `requestId`，重复调用返回 409 后会核对 Hub 中的字段。

求职助手新增 `POST /api/imports/job-agent`，请求只接收 `sourceRunId`、案例集 SHA-256、运行标签、结果来源、可空模型 ID、开始时间及逐例 `id` / `task` / `passed` / `checks[{name,passed}]`。Hub 以 `job-agent` 保存运行，以独立表保存案例与检查项，返回 `runId`、报告哈希和是否新导入；`GET /api/runs/{runId}/job-results` 可查询结果。相同 `sourceRunId` 和相同规范化内容返回同一运行；同一 ID 内容变化返回 409。重复案例 ID、重复检查名、整例结论与检查项不一致、人工复核来源和离线夹具声明模型均拒绝。求职助手本地报告用独占创建保存，重试原文件不会重新运行模型。

求职助手离线规则结果与 QA 的 Hit@k、MRR 等指标属于不同任务和分母，数据库和页面分别展示；`GET /api/comparisons` 仍只支持同口径 QA 报告，不计算跨项目“准确率”。求职助手的人工复核和跨项目统一指标不在本阶段内。

## 使用入口

QA 先按原项目说明采集预测，再评分。下列选项会在评分完成后导入 Hub：

```powershell
cd D:\qa-system
.\.venv\Scripts\python.exe eval\run_eval.py --predictions eval\predictions.jsonl --output eval\reports\run.report.json --run-label example --hub-url http://127.0.0.1:8080 --calls-file eval\predictions.calls.jsonl --model-id example-model
```

失败后使用原报告和原调用文件运行 `eval/publish_to_hub.py --report <报告> --calls-file <调用明细> --hub-url <地址> --model-id <模型>`；不重新采集或评分。首次发布应先核对报告与调用文件来自同一次评测。

求职助手默认仍只在终端输出离线检查。显式 `--hub-url` 才保存并导入规则报告；live 模式仍需同时指定 `--live --provider`，可能产生真实模型费用，本轮未执行。已有报告可用 `--retry-report-file` 重试，live 调用明细可同时通过 `--retry-usage-file` 重传：

```powershell
cd D:\Agent\job-agent
.\.venv\Scripts\python.exe -m scripts.evaluate_outputs --hub-url http://127.0.0.1:8080
```

价格仍在 Hub `/api/prices` 单独登记。缺少供应商 token 或已登记价格时，调用费用继续显示不可核算；旧 QA 基线不推断 token。
