# 第四阶段：模型调用用量与费用核算

更新日期：2026-11-20。

## 本阶段范围

新增独立的模型调用记录和不可变的模型价格版本。调用记录通过本项目 API 手动写入，不从多用户 RAG 知识库问答系统（`qa-system`）的旧报告推断 token，也没有调用真实模型或修改两个原项目。前端在已导入报告的运行详情中展示该运行的调用用量与核算状态。两个原项目的自动上报仍属于第五阶段。

## 数据与计算口径

`V4__create_model_usage.sql` 建立 `model_price_versions` 和 `model_call_usage`。价格按模型 ID 与版本唯一保存，包含币种及每百万输入、输出 token 的单价；没有更新或删除接口。每条调用保存运行 ID、请求 ID、模型 ID、可选耗时、可选的成对输入/输出 token、可选价格版本、计算结果与 UTC 记录时间。同一运行的请求 ID 唯一，重复写入返回 409。

价格由操作员登记，本项目不验证供应商账单或价格来源。`inputTokens` 和 `outputTokens` 只能来自明确上报的用量；两个字段必须同时给出，零与缺失不同，单项上限为 10 亿以匹配存储精度。单价最多 8 位小数且低于 1 万亿。费用计算为 `(输入 token × 输入单价 + 输出 token × 输出单价) / 1,000,000`，用 `BigDecimal` 保存到小数点后 12 位。调用缺少 token 时为 `MISSING_USAGE`；有 token 但未指定价格版本时为 `MISSING_PRICE`；两者都有才为 `CALCULATED`。指定不存在的模型价格版本返回 404。

运行汇总列出全部调用，费用金额在 JSON 中以十进制字符串返回，避免前端浮点数丢失精度。`inputTokens` / `outputTokens` 只合计已提供用量的调用。没有调用时状态为 `NO_CALLS`；存在不可核算调用时为 `INCOMPLETE`，总费用为 `null`；有不同币种时为 `MIXED_CURRENCY`，总费用也为 `null`；仅当全部调用可核算且币种一致时为 `CALCULATED`。不同币种不做汇率换算。报告中的 `model_calls` 是原项目包装器次数，不能代替本表的 token 或供应商计费次数。

## 接口示例

先创建价格版本，再为已有运行登记调用。以下金额和 token 均为**演示值**，不得当作原项目实测或真实供应商价格。

```http
POST /api/prices
Content-Type: application/json

{"modelId":"example-model","version":"demo-2026-11","currency":"USD","inputPerMillion":1.25,"outputPerMillion":10.50}
```

```http
POST /api/runs/{runId}/calls
Content-Type: application/json

{"requestId":"example-request-1","modelId":"example-model","latencyMs":300,"inputTokens":5000,"outputTokens":1500,"priceVersion":"demo-2026-11"}
```

读取使用 `GET /api/prices` 和 `GET /api/runs/{runId}/usage`。价格与调用创建成功均返回 201；运行不存在返回 404；输入无效返回 400。上例单次费用为 `0.022000000000 USD`。未提供用量时可省略两个 token 字段；未登记价格时可省略 `priceVersion`，接口会保存记录并标记不可核算。

## 验证与限制

本机 Oracle JDK 17.0.12、Maven 3.9.16、Node.js 24、pnpm 11。设置 `JAVA_HOME=E:\java17` 后，`mvn -B package` 在沙箱外完成 **21 个测试，0 失败、0 错误**并打包可运行 jar；`cd frontend; pnpm.cmd build` 通过 TypeScript 检查和 Vite 构建。普通沙箱内的 Mockito 测试会因本机 JVM attach 管道权限停住，因此完整 Maven 测试在允许该本机操作的执行环境中运行；仓库未为此改变测试配置。

使用本机已有 `mysql:8.4` 镜像启动一次性隔离库，在 `127.0.0.1:33308` 上实际启动后端。Flyway 从空库依次应用 V1～V4，最后为 v4。手动创建演示运行、演示价格和一条 5000 输入 / 1500 输出 token 的调用，API 返回单次和汇总费用 `0.022 USD`、状态 `CALCULATED`；再加入一条未提供 token 的调用，返回 `MISSING_USAGE`，运行汇总变为 `INCOMPLETE` 且 `totalCost=null`；重复请求 ID 返回 409。演示值与原项目报告无关。此处验证了本机数据库迁移和主要读写路径，尚未做并发、重启恢复或真实供应商账单核对。

当前没有真实 token 数据，也没有已核验的供应商价格；因此不能声称原项目既有报告已可计算费用。接口没有登录鉴权，仍只绑定本机地址。调用由手动 API 写入，无法证明其等于供应商实际账单；缺少请求 ID 对应的原始调用证据时，需由上报者承担来源核对。第五阶段才处理两个原项目自动上报，第六阶段才补完整端到端演示。
