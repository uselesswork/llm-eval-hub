# 第六阶段：隔离集成测试、Compose、CI 与演示

更新日期：2026-11-20。

## 完成范围

本阶段给 Hub 增加独立的 MySQL 8.4、Spring Boot API 和 Nginx 托管的 Vue 页面 Compose 栈，以及只使用仓库内报告和合成规则结果的端到端冒烟脚本。脚本验证 QA 报告导入与去重、求职助手规则报告导入与冲突、同口径对比、页面实际渲染、前端代理和整栈重启后的数据保留。CI 按相同顺序运行 Maven、前端构建和 Compose 冒烟。两个原项目未在本阶段修改或运行，未调用真实模型。

## 文件职责与数据流

| 文件 | 职责 |
| --- | --- |
| `compose.yaml` | 启动 MySQL、后端和前端；数据库使用具名卷，前后端仅绑定本机端口 |
| `Dockerfile`、`frontend/Dockerfile`、对应 `.dockerignore` | 把已在宿主机完成的 jar 和 `dist/` 打入运行镜像；不复制本地依赖、源码环境文件 |
| `frontend/nginx.conf` | 提供 Vue 静态资源，并代理 `/api/`、`/health` 到后端 |
| `src/main/resources/application.yml` | 默认仍绑定 `127.0.0.1`；Compose 用 `SERVER_ADDRESS=0.0.0.0` 让容器内服务可访问 |
| `scripts/smoke.py` | 从仓库内报告和合成规则结果导入，检查 API、幂等、比较及重启恢复 |
| `scripts/check-page.mjs`、`frontend/src/App.vue` | 用 Chrome 无头模式检查真实数据在对比页渲染；页面支持 `baselineId`、`candidateId` 查询参数直达比较 |
| `.github/workflows/ci.yml` | 推送和 PR 时执行单测、构建、Compose 冒烟和清理 |
| `src/test/resources/qa-system/2026-11-18-stage14-regression-luna.report.json` | 同口径第二份报告测试副本，来源为 `D:\qa-system\eval\baselines\2026-11-18-stage14-regression-luna.report.json` |

报告导入使用已有的 `POST /api/imports/qa-system`，第二份报告与仓库原有 `2026-11-17-gpt-6-luna.report.json` 共享案例集哈希、五题集合、`k=5` 和指标定义。`GET /api/comparisons` 返回九项指标及五题变化。求职助手用脚本生成两条**合成离线规则结果**，导入已有 `POST /api/imports/job-agent`；重复提交返回原 ID，改动相同 `sourceRunId` 的内容返回 409。`GET /api/runs/{id}/results`、`/job-results` 和 `/api/runs` 也经前端 Nginx 代理检查。浏览器测试打开带两条运行 ID 的 Vue 对比页，并检查实际报告标签与“指标差值”已渲染。

这些 QA 报告是原项目此前保存的评分产物，`LIVE_MODEL` 是其原有来源声明；本阶段只重放文件，没有再次执行模型，也没有把原报告中的调用次数当作 token。求职助手报告是合成夹具，不代表真实求职助手质量。

## 新环境运行与演示

需要 Docker Compose、Java 17、Maven、Node.js 24、pnpm 11、Python 3 和 Chrome/Chromium。先在仓库根目录构建后端与前端，再启动 Compose。Compose 镜像只包装已构建产物，因此修改 Java/Vue 代码后要重新构建并运行 `docker compose up -d --build`。容器基础镜像来自公共 ECR；Maven/npm 依赖由宿主机按 `pom.xml` 和 `frontend/pnpm-lock.yaml` 安装。

```powershell
$env:HUB_DB_PASSWORD = [guid]::NewGuid().ToString('N')
mvn -B verify
cd frontend
pnpm install --frozen-lockfile
pnpm build
cd ..
docker compose up -d --build
python scripts/smoke.py seed
node scripts/check-page.mjs
```

打开 `http://127.0.0.1:5173/` 查看运行列表、两份 QA 报告的对比和求职助手规则结果。后端直连地址为 `http://127.0.0.1:18080/`；原项目显式上报时可使用这个地址。端口可在启动前通过 `HUB_WEB_PORT`、`HUB_API_PORT` 改动，并向冒烟脚本传 `--web`、`--api`。本地 Chrome 不在常见路径时设置 `CHROME_BIN`。

检查数据卷在整栈重建后保留：

```powershell
docker compose down
docker compose up -d
python scripts/smoke.py verify
node scripts/check-page.mjs
```

`seed` 将三条运行 ID 写入被忽略的 `target/stage6-smoke-state.json`；`verify` 读取它，并查询原运行、逐例结果和对比。`docker compose down` 不删除具名卷；演示结束后如要删除**本项目 Compose 数据卷**，运行 `docker compose down -v`。不要对已有业务库使用这条清理命令。示例只在当前终端生成一次性数据库密码；仓库不保存密码或 `.env` 文件。默认端口只绑定 `127.0.0.1`，不能作为公网部署方案。

## CI 与实际验证

`.github/workflows/ci.yml` 在 GitHub 推送和 PR 上使用 `ubuntu-24.04` 运行 `mvn -B verify`、`pnpm install --frozen-lockfile`、`pnpm build`，随后创建一次性数据库密码、启动 Compose、执行 `seed` 和 Chrome 页面检查；再以 `docker compose down` / `up -d` 重启整栈并执行 `verify` 和页面检查；最后无论成功失败都清理容器和卷。CI 使用[该运行器镜像列出的 Chrome](https://github.com/actions/runner-images/blob/main/images/ubuntu/Ubuntu2404-Readme.md)；仓库没有存储 CI 数据库密码。首次推送提交 `62d6281` 触发的 [CI 运行](https://github.com/uselesswork/llm-eval-hub/actions/runs/44728771545) 已成功结束；后端测试、前端构建、导入与比较、整栈重启后的结果与页面检查及清理步骤均为成功。

本机验证：`mvn -B verify` 完成 23 个测试，0 失败；`pnpm build` 完成 Vue 类型检查与 Vite 构建；`docker compose config --quiet` 通过。Docker 29.7.2、Compose v5.5.0 在一次性项目名下从空卷启动 MySQL 8.4，并运行 Flyway V1～V5。`scripts/smoke.py seed` 验证两份 QA 报告、九项指标、五题比较、求职助手两条合成规则结果及重复导入；`scripts/check-page.mjs` 在 Chrome 中读到实际标签和指标差值。随后执行 `docker compose down`、`up -d`，`verify` 与浏览器检查再次通过；最后删除本次专用容器、网络和卷。本机 Docker Hub 连接超时，因此基础镜像改用可访问的公共 ECR；容器内 npm 连接中断后改为宿主机先构建，最终流程实际通过。

## 限制

测试用的是仓库内已保存 QA 报告及合成求职规则结果，没有验证两个原项目的真实模型调用、真实 token/价格、供应商费用或上报身份。浏览器冒烟检查对比页关键文本与数据，不覆盖每个交互和视觉布局。Compose 面向本地演示，没有登录鉴权、TLS、备份或公网部署配置；共享环境和生产部署需要另行设计。对比仍只接受同口径 QA 报告，不合并两个项目的指标。
