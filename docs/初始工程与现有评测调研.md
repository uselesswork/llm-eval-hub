# 初始工程与现有评测调研

核对日期：2026-11-18。本轮仅阅读两个原项目文件；没有调用模型、读取密钥、修改原项目或导入数据。本仓库仍没有评测接口、持久化或跨项目接入。

## 初始工程

本仓库使用 Java 17、Maven，入口为 `dev.llmevalhub.Main`。`pom.xml` 固定编译插件 3.15.0 和运行插件 3.6.3；入口只打印骨架状态。构建、运行与本机验证结果见根目录 README。

## qa-system：已有真实预测与评分报告

- 案例：`D:\qa-system\eval\dataset.jsonl`（5 题）、`D:\qa-system\eval\stage16\dataset.jsonl`（扩展样本）。每题有 `id`、`category`、`question`、`relevant_sources`、`answer_contains`、`should_refuse`；部分另有 `history`、`answer_excludes`。固定语料在各自 `corpus/`。来源：上述案例文件、`D:\qa-system\eval\README.md`。
- 采集：`D:\qa-system\eval\collect_predictions.py` 调用真实 Embedding 和 RAG/LLM，逐题写 JSONL：`id`、有序 `retrieved_sources`、`cited_sources`、`answer`、`refused`、`latency_ms`、`model_calls`、`vector_backend`、`model`。`model_calls` 是包装器计数；延迟是逐题链路耗时。来源：该脚本。`D:\qa-system\src\llms\openai_chat.py` 在非流式调用返回元数据中取得 `prompt_tokens`、`completion_tokens`、`total_tokens` 和单次耗时，但采集脚本未把这些用量写入预测或报告。
- 评分：`D:\qa-system\eval\run_eval.py` 校验案例与预测 ID 一一对应，写 JSON 报告，包含 `sample_count`、`answerable_count`、`refusal_count`、`k`、各聚合指标、逐题 `cases`，以及 `run.label`、UTC 时间、Python 版本、案例及预测 SHA-256、预测路径；传入语料目录时还记录逐文件哈希。来源：该脚本、`D:\qa-system\eval\metrics.py`。
- 已落盘基线：`D:\qa-system\eval\baselines\2026-11-17-gpt-6-luna.predictions.jsonl` 与同名前缀 `.report.json` 为 5 题真实模型基线，报告为 4 道可回答题、1 道拒答题；`2026-11-18-stage16-qdrant-luna` 前缀报告为 10 题，另有旧题回归报告。来源：`D:\qa-system\eval\baselines\` 中对应文件、`D:\qa-system\eval\README.md`。文档明确限定独立短语料与特定后端，不能外推生产效果；首次五题基线不覆盖 MySQL、Qdrant、Redis、HTTP 或浏览器耗时。

未来报告导入可以直接读取案例 ID、类别、评分结果、样本分母、`k`、运行标签/时间、文件哈希、逐题延迟和调用次数，并从配对预测文件读取模型、向量后端、回答及来源。现有评分报告本身不含逐题模型标识、原始回答和召回顺序；首次报告也没有语料哈希。尚缺稳定的提示词版本、运行 ID、每次调用关联 ID、各次调用 token 用量、价格版本、费用、人工复核人/结论。`run.label` 只是自由文本，不能当作这些字段的正式版本号。来源：上述评分与采集脚本、基线文件。

## AI 求职助手：离线虚构案例规则评估

- `D:\Agent\job-agent\evals\cases.json` 保存 20 个虚构案例，分 `resume` 9、`job` 7、`match` 4；逐例有 `id`、`task`、`expected`、预置 `output` 和 `review`，按任务另有虚构输入。`review.record` 写的是编制和规则复跑，人工语义复核仍待完成。来源：该文件、`D:\Agent\docs\第十七阶段-AI评估集扩充.md`。
- `D:\Agent\job-agent\app\services\evaluation.py` 用 Pydantic 校验结构，并检查证据字面包含、期望技能/条件、最低数量及匹配分数加权接近程度；返回逐例 `id`、`task`、`passed`、`checks[{name,passed}]`。字面命中不证明事实或语义正确。来源：该文件。
- `D:\Agent\job-agent\scripts\evaluate_outputs.py` 默认读取预置输出，终端打印逐例状态、失败检查名及汇总，不写 JSON 报告；只有显式 `--live --provider` 才会调用真实模型，并打印逐例耗时与模型标识。`D:\Agent\job-agent\app\services\llm.py` 返回解析后的 JSON，没有传递供应商 usage。来源：上述脚本与客户端。第十七阶段文档记录离线预置输出 20/20、结构 20/20、字面证据检查 24/24、硬性条件漏判检查失败 0、评分一致性 4/4；明确没有运行真实模型或完成真人语义复核。来源：`D:\Agent\docs\第十七阶段-AI评估集扩充.md`。

未来可直接读取案例 ID、任务类型、预期条件、预置输出和规则检查名称/结果，但当前没有持久化的逐次评估报告；需要后续阶段采集运行时间、模式、提供商/模型、可追溯的输出来源、逐例检查结果和耗时。还缺案例集版本或哈希、提示词版本、运行 ID、调用级 token、价格版本/费用，以及真正的人工审核人、时间、争议和结论。不能把 `review` 编制记录当成人工复核完成。来源：上述案例、脚本、客户端及第十七阶段文档。

## 指标口径不可混用

| 项目 | 指标与分母 | 来源与限制 |
| --- | --- | --- |
| qa-system | `Hit@k`、`MRR@k`、引用准确率、答案包含率仅对有标准证据的可回答题取均值；拒答正确率仅对无答案题；延迟 P50/P95 对全部题；调用总数为逐题求和 | `D:\qa-system\eval\metrics.py`、`eval\README.md`。答案包含是字符串核对，不是语义准确率。 |
| AI 求职助手 | 整例通过为所有已执行检查同时通过；结构数以案例为分母；证据数以实际执行的证据检查为分母；硬性条件是指定检查失败项个数；评分一致性只覆盖匹配题 | `D:\Agent\job-agent\scripts\evaluate_outputs.py`、`app\services\evaluation.py`、`D:\Agent\docs\第十七阶段-AI评估集扩充.md`。现有结果来自离线预置输出。 |

两边的任务、样本、分母和结果来源均不同，不能汇成统一“模型准确率”。未来接入时须分别保存数据来源（真实模型/离线预置/人工审核）、指标定义、分母、案例集版本与运行配置；当前仅为调研结论，未实现采集或接入。
