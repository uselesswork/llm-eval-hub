# LLM Eval Hub：跨项目模型评测与调用管理

本项目计划用 Java 和 Spring Boot 汇总多个 AI 应用的评测运行、模型调用用量与人工复核记录。首批接入对象是多用户 RAG 知识库问答系统（项目目录和来源标识为 `qa-system`）与 AI 求职助手：两个项目各自保留业务逻辑，由本项目接收统一格式的结果，便于比较模型或提示词调整前后的表现。

> 当前状态（2026-11-19）：第三阶段已加入同口径报告对比、自动失败分类、人工复核历史和 Vue 3 本地页面；实际验证范围见[第三阶段说明](docs/第三阶段-版本对比与前端展示.md)。两个原项目尚未自动上报，AI 求职助手尚未接入。

## 一眼看懂项目目标

```text
多用户 RAG 知识库问答系统 ─┐
                         ├→ 标准化评测与调用记录 → LLM Eval Hub API → Vue 前端展示（本地版）
AI 求职助手 ──────────────┘                                       ├→ 按项目/版本对比
                                                                 ├→ 用量与费用核算
                                                                 └→ 人工复核与失败归因
```

两个原项目的输出范围不同：知识库问答系统已有小样本真实模型评测报告，AI 求职助手目前主要是虚构案例的离线规则评估。本项目应保留“离线预置输出”“真实模型输出”“人工复核”三种来源标签，不将它们的通过率混为一个指标。

## 为什么做

现有两个 AI 项目的评测结果分别保存在脚本、JSON 报告或命令行输出中。跨项目查看模型版本、案例集变化、失败原因和调用成本时，需要手工整理；其中费用和人工复核记录仍有明确空缺。本项目围绕这个已经出现的问题建设一个独立的 Java 后端，同时展示 Spring 体系下的接口设计、事务、SQL 和集成测试能力。

## 规划的技术栈与边界

- **当前核心**：Java 17、Spring Boot、Spring MVC、MyBatis、Spring JDBC、MySQL、Flyway 和 JUnit。具体依赖以 `pom.xml` 为准；Testcontainers 尚未加入。
- **当前前端**：仓库根目录的 `frontend/` 使用 Vue 3、TypeScript 和 Vite。前端通过 `/api` 获取真实数据；Maven 构建后端，pnpm 独立构建前端。当前仅提供本地开发代理，生产托管留待后续阶段。
- **跨项目接入**：约定统一的运行 ID、项目来源、案例集版本、模型标识、指标定义和结果来源。上报接口需处理重复提交与版本兼容，原项目可通过 HTTP 客户端或报告导入接入。
- **费用核算**：只在取得供应商返回的 token 用量和已记录的价格版本时计算；缺少用量或价格时明确标记“无法计算”，不按字符数猜测实际费用。
- **按需扩展**：只有出现缓存、限流或异步批量处理的实测需求，再评估 Redis、任务队列等组件。首版不预设微服务拆分。
- **数据保护**：默认只接收指标、运行元数据和必要的错误分类，不上传真实简历、知识库原文、完整提示词、API Key 或数据库密码。

## 规划的数据与接口

运行元数据、知识库问答系统的报告指标、同口径比较和人工复核已实现；调用用量仍是后续方向：

1. 已实现保存和查询评测运行元数据：来源项目、运行标签/时间、可空模型和提示词版本、案例集版本、结果来源和状态。
2. 已实现导入知识库问答系统的逐例结果和汇总指标，保存案例 ID、类别、检查值、分母、指标定义版本与来源哈希；第三阶段加入规则失败分类和追加式人工审核记录。
3. 后续保存调用用量：请求关联 ID、耗时、输入/输出 token、价格版本和可核算费用。
4. 已实现按项目、案例集版本、模型筛选运行，并在同一案例集、结果来源、指标定义及分母一致时对比两次已导入报告，显示指标差值与新增失败分类。

同名指标也可能使用不同样本或分母；比较接口会核对来源、案例集、题目集合、`k`、指标定义和分母。当前接口及表见[第一阶段](docs/第一阶段-服务与评测运行.md)、[第二阶段](docs/第二阶段-qa-system报告导入.md)及[第三阶段说明](docs/第三阶段-版本对比与前端展示.md)。

## 前端展示

首版 Vue 页面已在第三阶段实现：运行列表支持按来源项目、案例集和模型标识筛选；运行详情展示逐例结果、失败分类和结果来源；对比页只展示后端确认同口径的两次运行，并标出新增或已消失的失败分类；人工复核页保存审核结论及历史。页面区分真实模型输出、离线预置输出和人工复核，对缺失的用量或费用显示“暂无数据”。

第四阶段取得真实 token 用量及价格版本后，再加入用量和费用展示；第五阶段接入 AI 求职助手后，扩展跨项目筛选。`frontend/node_modules/` 和构建产物被忽略，锁文件留在仓库中。当前无生产托管或登录鉴权，不应把本机 API 直接暴露公网。

src/main/resources/db/migration/         Flyway 数据库迁移

frontend/                                Vue 3 + TypeScript + Vite 本地页面
.gitignore                               IDE、构建产物和本地环境文件忽略规则

安装 JDK 17、Maven 3.9.16 和 MySQL 8，创建空库和专用账号，并在 PowerShell 中从仓库根目录设置 `DB_URL`、`DB_USER`、`DB_PASSWORD`。具体权限和示例见[第一阶段说明](docs/第一阶段-服务与评测运行.md)。运行：

```powershell
mvn -B package
java -jar target\llm-eval-hub-0.1.0-SNAPSHOT.jar
```

应用默认监听 `127.0.0.1:8080`，提供运行、报告导入与结果、比较、分类和人工复核 API；接口清单见[第三阶段说明](docs/第三阶段-版本对比与前端展示.md)。数据库迁移在启动时执行。导入接口需上传原项目的 `.report.json` 文件，并明确声明 `resultSource`；示例见[第二阶段说明](docs/第二阶段-qa-system报告导入.md)。仓库没有真实密码或容器配置。

前端使用 Node.js 24 与 pnpm 11，从独立终端启动：

```powershell
cd frontend
pnpm install --frozen-lockfile
pnpm dev
```

打开 `http://127.0.0.1:5173/`。开发代理将 `/api` 请求转发到本机后端 `8080`；`pnpm build` 会先检查 TypeScript，再生成静态构建产物。启动与限制详见[第三阶段说明](docs/第三阶段-版本对比与前端展示.md)。

本机默认 `java` 启动器没有正常返回；实际验证显式选择 `E:\java17`，使用以下命令（其他机器将路径换为自己的 JDK 17 安装位置）：

```powershell
$env:JAVA_HOME = 'E:\java17'
$env:Path = "$env:JAVA_HOME\bin;$env:Path"
mvn -version
mvn -B package
java -jar target\llm-eval-hub-0.1.0-SNAPSHOT.jar
```

本机 JDK 为 Oracle 17.0.12，Maven 为 3.9.16。各阶段具体构建、测试与数据库验证结果见对应[第一阶段](docs/第一阶段-服务与评测运行.md)、[第二阶段](docs/第二阶段-qa-system报告导入.md)和[第三阶段说明](docs/第三阶段-版本对比与前端展示.md)；上面的环境变量路径仅适用于本机。
